# PiPER 桌面原点布局调整设计

## 目的

修正当前护理桌在高度方向穿过机械臂的问题，同时保持 PiPER 的 `world`、`base_link` 和 Gazebo 机械臂模型位于现有零点，不修改官方 `piper_ros` 的 URDF、MoveIt2 配置或控制器。调整后以桌面上表面作为 `z=0`，便于后续直接根据物体高度计算抓取目标。

本文档取代原固定杯子抓取设计中“桌面中心 `z=0.225 m`、杯子中心 `z=0.30 m`”的场景坐标；原设计的其余架构、安全边界和抓取状态机保持有效。

## 坐标约定

机械臂基座原点保持 `(0, 0, 0)`。机械臂位于桌子短边中点，桌面从该处向 `+X` 方向延伸，桌面完整可视范围为 `x=0.00～0.70 m`、`y=-0.25～0.25 m`。桌板厚度为 `0.05 m`，上表面为 `z=0`，因此桌板中心为 `z=-0.025 m`。

护理桌总高度保持约 `0.25 m`。Gazebo 默认地面模型需要被场景管理节点删除，并在 `z=-0.25 m` 处生成新的静态地面；桌腿从桌板下表面延伸到新地面。此变化只调整环境，不移动机械臂坐标系。

## 杯子位置

圆柱杯半径保持 `0.035 m`、高度保持 `0.10 m`。杯子初始中心改为 `x=0.40 m、y=-0.12 m、z=0.05 m`，因此杯底正好位于桌面 `z=0`。杯子跟随节点、Gazebo 生成位姿与 MoveIt2 圆柱碰撞体必须读取同一组参数，不允许分别写死坐标。

后续安全交付位置同样以桌面为零高度，杯子中心高度使用 `z=0.05 m`。本次只调整场景坐标，不改变自动抓取状态机、SSVEP 目标选择或 EOG 确认逻辑。

## Gazebo 场景

场景管理节点新增 `care_floor`：重置场景时依次清理原 `ground_plane`、旧 `care_floor`、`care_table` 和 `medicine_cup`，然后生成新地面、护理桌和杯子。护理桌的外观模型从 `x=0` 开始完整显示，机械臂仍由原官方启动流程在 `(0,0,0)` 生成。

自定义地面使用静态薄盒体，其上表面位于 `z=-0.25 m`，大小应明显超过桌子和机械臂活动范围。地面、桌子和杯子重置成功后，场景节点才发布 `scene_ready=true`；任何一个模型生成失败时保持 `false`。

## MoveIt2 规划场景

MoveIt2 中桌面碰撞体的上表面同样为 `z=0`。为避免机械臂基座与桌面接触面被碰撞检测器判为初始碰撞，规划用桌面盒体从 `x=0.10 m` 开始，到 `x=0.70 m` 结束；Gazebo 中的可视桌面仍覆盖 `x=0～0.70 m`。这 `0.10 m` 只代表基座安装避让区，杯子和后续任务目标不得放入该区域。

规划场景不必加入新地面碰撞体，因为地面位于桌面以下且不属于正常运动空间。桌面和杯子仍通过 `/apply_planning_scene` 更新，重置后 RViz2 与 Gazebo 的杯子位置必须一致。

## 参数调整

场景 YAML 增加或调整以下参数：

- `floor_name: care_floor`
- `floor_z: -0.25`
- `table_x: 0.35`
- `table_y: 0.00`
- `table_surface_z: 0.00`
- `table_center_z: -0.025`
- `planning_table_min_x: 0.10`
- `cup_x: 0.40`
- `cup_y: -0.12`
- `cup_z: 0.05`

桌腿高度必须由 `table_surface_z`、桌板厚度和 `floor_z` 计算，不能继续使用仅适用于正高度桌面的旧公式。所有尺寸需要在启动时检查为正值，并检查杯子位于桌面平面范围与基座避让区之外。

## 验收标准

1. Gazebo 中机械臂基座位于桌子短边中点，桌板不再穿过机械臂主体，桌腿落在新地面上。
2. `world` 和 `base_link` 原点没有改变，机械臂控制器与已有 RViz2 手动规划仍可正常使用。
3. 杯底位于桌面上表面，Gazebo 和 RViz2 中杯子位置一致。
4. MoveIt2 当前状态不是碰撞状态，规划轨迹不会穿过规划用桌面碰撞体。
5. 调用场景重置服务后，新地面、桌子和杯子恢复到相同位置，不出现重复模型。
6. `simulation_only=false` 时仍拒绝启动，不向真实机械臂发送控制命令。
