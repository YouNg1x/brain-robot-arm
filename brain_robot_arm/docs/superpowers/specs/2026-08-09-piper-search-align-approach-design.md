# PiPER 腕部相机自动搜索、对准与接近设计

## 1. 目标与本阶段范围

在现有 PiPER、Gazebo、MoveIt2、腕部 RGB-D 相机和红杯检测器基础上，增加一个独立的视觉运动控制节点。当相机中没有目标时，机械臂先进入占用空间较小的抬臂观察姿态，再让 J1 与 J5 同时进行独立往返搜索；发现目标后停止搜索，用腕部相机把目标调整到画面中心；目标稳定居中且深度有效后，才允许沿相机光轴低速接近，并在 0.18 m 处停止。

本阶段只完成“准备、搜索、对准、接近、停止”，不自动闭合夹爪，也不连接实体机械臂。代码和接口必须可复用于实体 PiPER、腕部 Gemini2 和 SSVEP+EOG 头环，Gazebo 与实体差异只能放在启动文件、参数、标定和运动后端中，不能写死在视觉算法或状态机中。

## 2. 已确认的关节功能映射

本项目以当前 PiPER 模型和用户观察到的实际运动效果为准。J1 位于底座，负责机械臂整体左右摆动，用于画面水平方向搜索；J2、J3 在搜索前抬起并收拢机械臂，减少 J1 扫描时的占用面积，同时给腕部留下活动空间；J5 负责相机俯仰、上下扫描和画面垂直方向修正；J4、J6 共同保持相机画面水平，禁止用它们承担垂直搜索。当前仿真已按用户观察更正为 J5 从 0 增加到 +0.3 rad 时相机向下看，因此向下对准使用正方向；该方向必须通过 Gazebo 现象验证，不能直接外推到实体机械臂。

关节名称、正方向和零偏均通过参数配置。仿真中的初始映射为 `horizontal_joint=joint1`、`prepare_joints=[joint2,joint3]`、`vertical_joint=joint5`、`horizon_joint_names=[joint4,joint6]`。实体机械臂接入时必须用低速点动重新确认正负方向和两个水平锁定角，不能仅凭 Gazebo 现象认定实体方向相同。

## 3. 方案选择

方案一是保留分层栅格搜索，J1 每扫完一行后 J5 才改变角度，覆盖规则但两个关节不能同时搜索。方案二是用正弦或 Lissajous 曲线同时驱动 J1/J5，运动更平滑，但需要额外的时间相位和频率标定。选定方案三：MoveIt2 先规划 J2、J3 抬臂观察姿态，J4、J6 回锁到各自标定的水平角，J1 与 J5 再以不同速度独立进行三角波往返；任一关节到达自身边界就立即反向，不等待另一关节。这种方式修改范围小、覆盖不会长期重复在同一条对角线上，也便于实体模式独立降低两个关节的速度和范围。

## 4. 软件结构与接口

现有 `cup_detector_node` 保持为纯感知模块。它发布 `/brain_robot_vision/target_pixel`（`PointStamped`，x/y 为像素中心，z 为米制深度）、`/brain_robot_vision/pixel_error`（`Vector3Stamped`，x/y 为相对画面中心的像素误差，z 为目标面积比例）、`/brain_robot_vision/target_valid`、`/brain_robot_vision/depth_valid` 和调试图像。控制器使用带时间戳的目标或误差消息判断数据新鲜度，两个 Bool 话题只作为有效性门控，不单独代表新数据。

新增 `visual_search_controller`，只负责状态机、误差死区、速度限制、目标丢失处理和安全门控，不直接依赖 Gazebo 话题。运动接口分为两层：MoveIt2 负责进入抬臂观察姿态和以后可能的任务级轨迹；MoveIt Servo 负责搜索、对准和接近阶段的低速增量运动。搜索与对准使用同一条 `JointJog` 同时控制 J1/J5 并回锁 J4/J6，接近使用相机坐标系下零角速度的 `TwistStamped` 保持末端姿态；两类指令不会同时发送，切换或停止时对全部受控关节发送显式零速度，停止路径不会继续执行水平回锁。

运动后端分为 `simulation` 和 `piper` 两个配置。仿真后端连接 Gazebo 的 ros2_control；实体后端以后连接官方 PiPER 驱动。相机输入也只通过话题重映射切换虚拟 RGB-D 与 Gemini2 对齐深度流。核心状态机不读取模型名称、不使用 Gazebo 服务、不写死虚拟相机坐标。

## 5. 状态机与运动规则

状态顺序为：

`IDLE -> PREPARE -> SEARCH -> ALIGN -> APPROACH -> REACHED`。

任何状态都可以进入 `STOPPED` 或 `FAULT`。`IDLE` 不发布非零运动指令；收到授权后进入 `PREPARE`。仿真观察姿态经腕部相机视角复测后修订为 J1=0.00、J2=+0.98、J3=-0.75、J4=0.00、J5=+0.30、J6=0.00 rad，MoveIt2 必须先完成碰撞检查和规划，规划失败则保持停止。这个姿态只是仿真初值；实体配置中不提供可执行默认值，必须完成标定并显式设置 `real_motion_enabled=true` 才能运动。

`SEARCH` 中 J2/J3 保持观察位，J4/J6 回锁到标定的画面水平角。J1 在 `-0.35～+0.35 rad` 范围内以不超过 `0.12 rad/s` 的速度左右往返；J5 从 `+0.30 rad` 观察位开始，在 `-0.60～+1.10 rad` 范围内以不超过 `0.15 rad/s` 的速度上下往返。两者在每个控制周期同时发布速度命令，并分别检测自己的边界；任一关节到边界后只反转自己的方向，不停止或等待另一个关节。不同范围和速度使两者周期不同，避免轨迹长期退化为同一条重复对角线。搜索阶段前向分量始终为零，75 s 超时后进入 `STOPPED`，不会无限重复。

目标连续 3 个有效帧且消息未超时后，立即发零指令并进入 `ALIGN`。J1 根据水平像素误差 `dx` 低速修正，J5 根据垂直像素误差 `dy` 修正，J4/J6 继续锁定；具体正负号由仿真和实机各自的标定参数决定。两个误差连续 5 帧落入 25 px 死区，且深度连续有效后进入 `APPROACH`。

`APPROACH` 只发送相机光轴方向的低速前进速度。若任一像素误差超过 35 px，则前进速度立即归零并回到 `ALIGN`，不边偏移边盲目前进；误差恢复后才能继续。接近速度上限初始为 0.015 m/s，并随距离接近 0.18 m 线性减小。有效深度不大于 0.18 m 且连续稳定 5 帧后进入 `REACHED`，保持零速度，不自动夹取。

目标在 `ALIGN` 或 `APPROACH` 中丢失时，先在 200 ms 内停止所有非零指令。控制器围绕最后观察角度用 J1/J5 同时进行不超过 5 s 的独立小范围往返，局部范围分别为 0.08 rad 和 0.12 rad；局部J5边界必须被裁剪在全局 `-0.60～+1.10 rad` 范围内，J4/J6 仍保持水平。仍未找到则重新进入 `PREPARE`，随后只执行一次完整搜索；再次失败后进入 `STOPPED`，等待新的人工或脑机授权。

## 6. 安全门控与脑机接口预留

目标消息超过 0.6 s、深度无效、TF 不可用、MoveIt Servo 未就绪、控制器未激活、规划失败、碰撞或奇异点预警、关节接近软件搜索边界、用户取消、EOG 急停时，控制器立即发布零指令并禁止前进。控制循环目标频率为 20 Hz；任何非零命令都带看门狗，超过 0.2 s 未更新就失效。软件搜索边界远小于机械关节极限，不能用 URDF 的机械极限直接作为搜索范围。

SSVEP 以后只负责选择目标或任务，EOG 负责确认、取消和紧急停止。它们通过任务级命令接口改变 `IDLE/STOPPED` 的授权状态，不直接发送关节命令，也不能绕过深度、碰撞、限位和数据超时门控。实体模式默认 `real_motion_enabled=false`，只有完成 CAN、驱动、急停、关节方向、相机外参和工作区标定后才能人工解除。

## 7. 参数分层

公共参数保存状态机逻辑，例如连续有效帧数、像素死区、数据超时、停止距离和局部重捕获时长。`simulation.yaml` 保存仿真关节方向、候选观察姿态、Servo 话题和较保守的搜索速度。`piper_gemini2.yaml` 保存实体关节方向、实体观察姿态、Gemini2 彩色/对齐深度话题、相机坐标系和工作区限制，并保持运动禁用。这样从仿真切换到实体时只替换启动配置和运动后端，不修改检测器与状态机源码。

首版仿真参数为：J1 全局边界 `-0.35～+0.35 rad`、J5 观察位 `+0.30 rad`、J5 全局边界 `-0.60～+1.10 rad`、J1 搜索速度上限 `0.12 rad/s`、J5 搜索速度上限 `0.15 rad/s`、J4/J6 水平锁定目标均为 0.00 rad、目标获取 3 帧、对准稳定 5 帧、对准死区 25 px、重新对准阈值 35 px、最大接近速度 0.015 m/s、停止距离 0.18 m。所有数值均为仿真起点，不是实体机械臂的已验证参数；实体配置继续保持运动禁用和保守范围，不能复制这组大范围参数。

## 8. 可观察输出与操作方式

控制器发布当前状态、停止原因、J1/J5 当前搜索方向、最后目标时间、像素误差、深度和是否允许前进。相机调试窗口在现有杯子框和深度文字上增加状态文字，例如 `SEARCH J1=LEFT J5=DOWN`、`ALIGN`、`APPROACH` 或 `STOPPED: DEPTH_INVALID`。RViz 发布搜索边界和相机光轴标记，便于确认 J1/J5 的扫描方向、J4/J6 的水平锁定效果以及接近方向。

一键脚本仍负责启动 Gazebo、MoveIt2/RViz2、场景和视觉节点，但自动运动需要一次明确的开始命令；按一次 Ctrl+C、发送停止命令或触发 EOG 急停都会进入统一停止路径。仿真可以默认加载运动后端，实体模式绝不自动解除运动锁。

## 9. 验证顺序与验收标准

验证必须分层记录，不能用某一层成功代替另一层。第一层为 Windows 静态检查与 Ubuntu 编译；第二层为 Gazebo 无目标搜索，确认 J2/J3 保持抬起、J1/J5 同时运动且分别在自身边界反向、J5 正角使相机向下、J4/J6 保持画面水平、搜索阶段没有前进；第三层为 Gazebo 目标出现、居中、接近和丢失恢复；第四层只接 Gemini2 验证彩色图、对齐深度、帧率和 TF，不连接机械臂；第五层连接实体 PiPER，在夹爪空载、低速、有人值守和急停可用条件下逐关节验证；最后才接入 SSVEP 选择与 EOG 确认/取消/急停。

Gazebo 阶段通过条件为：无目标时 J1/J5 能持续同时扫描且不越过各自软件边界；任一关节反向时另一个关节不必停下；目标连续出现后停止扫描并进入对准；搜索阶段前向速度始终为零；目标未居中或深度无效时不前进；接近过程中目标偏离会立即暂停；在 0.18 m 附近稳定停止；目标丢失、停止命令和数据超时后 0.2 s 内无持续非零命令。实体 Gemini2、实体机械臂和头环均属于后续独立验证项，本设计不把仿真通过描述成实机通过。

## 10. 明确不包含的内容

本次不实现夹爪闭合、杯子抓取与放置，不训练通用目标识别模型，不直接读取头环厂商 SDK，不自动生成实体观察姿态，也不修改官方 PiPER 驱动。完成本阶段后，再把 `REACHED` 状态与已有抓取流程连接，并用 SSVEP 选择目标、EOG 确认执行。
