# PiPER 腕部 Astra 的未知空间禁止主动扫描设计

日期：2026-09-21
状态：设计已确认，尚未实施

## 目标

在不把当前实验桌、笔记本或支架坐标硬编码进仓库的前提下，使用现有 PiPER 六轴机械臂、腕部 Astra/Orbbec RGB-D 相机、关节反馈、TF 和 MoveIt 2，为每一次启动建立临时环境地图。机械臂仅在已被深度相机确认为空闲的空间内移动；任何候选扫描姿态或抓取路径经过未知/占据空间时均不执行。

目标仍是紫色方块的搜索、持续图像对齐和闭环抓取。扫描地图仅属于当前 ROS 会话，不保存为下一次运行的环境假设。

## 已确认的现有基础

- `cube_visual_search.launch.py` 已把 `/camera/depth/points` 配置给 MoveIt 的 `PointCloudOctomapUpdater`，OctoMap 坐标系为 `base_link`，分辨率为 0.02 m，最高更新率为 5 Hz。
- PiPER 的关节反馈经 `/piper_moveit_joint_states` 驱动 `robot_state_publisher`；腕部相机通过 `gripper_base -> camera_link` 静态 TF 与机器人树连接。
- Servo 已启用 MoveIt 场景碰撞检查。当前点云接入、自过滤和实机碰撞效果仍必须在 Ubuntu/RViz 验证，不能仅由配置视为已验证。
- MoveIt/OctoMap 能表示占据和空闲体素，但常规 MoveIt 规划不能自动把“未知”当作碰撞。因此本设计新增独立的未知空间门，而不以缺少点云作为可通行证据。

## 非目标

- 不在第一版加入固定桌子、电脑或支架的永久碰撞模型。
- 不让机械臂自由摆动、盲扫或为了建图而进入未确认空间。
- 不训练新检测网络，也不替换现有 HSV + RGB-D 方块检测器。
- 不承诺用单个腕部相机覆盖被自身、方块或工作台遮挡的全部空间。

## 方案比较与选择

### 已选择：腕部相机的严格临时扫描

首次零点复位后，系统在当前姿态先融合稳定深度帧。随后从 3--5 个预定义、关节限位内的观察候选姿态中选择下一项；每一条候选轨迹均先做已知占据碰撞检查和“未知即禁止”检查。通过才低速移动，失败则不动并报告原因。每个到达的观察位都融合新点云，直到满足目标/抓取走廊可观测条件或不存在可安全到达的新观察位。

优点是完全复用现有硬件，且不会把当前实验环境写死。代价是单一腕部相机的初始盲区可能使扫描无法继续；这是正确的保守停止，不是故障。

### 未选择：仅使用普通 OctoMap/MoveIt 规划

该方案可快速运行，但若未知体素没有明确占据标记，路径可能仍穿过相机没有观测到的区域。它不满足“不能先碰到物体”的要求。

### 后续扩展：固定外部 RGB-D 相机

若真实环境要求首次启动就覆盖大范围桌面/工作区，应增加或临时固定一台外部 RGB-D 相机。外部相机先建立环境地图，腕部 Astra 负责近距离目标对齐和微步抓取。该扩展不改变本设计的 Planning Scene、未知空间门或抓取接口，只增加一个地图输入源和外参标定。

## 系统数据流

```text
/joint_states -> piper_jog_adapter -> /piper_moveit_joint_states
                                      |
                                      v
                           robot_state_publisher
                                      |
                              TF: base_link ... gripper_base -> camera
                                      |
/camera/depth/points -----------------+-> 点云滤波/自过滤 -> OctoMap
                                                       |
                                                       v
                                             MoveIt Planning Scene

候选观察/抓取轨迹 -> 普通碰撞检查 + 未知空间走廊门
                                      |
                    +-----------------+------------------+
                    |                                    |
                  允许                                  拒绝
                    |                                    |
               低速执行                          保持原位并发布原因
```

## 组件与接口

### 1. 会话地图管理器

职责：在启动后创建空的会话状态，确认连续稳定的 `/camera/depth/points`、相机内参和 `base_link <- camera` TF 后开始接收点云。它不保存静态地图文件，也不会复用上次启动的占据结论。

输入：`/camera/depth/points`、`/tf`、`/tf_static`、`/piper_moveit_joint_states`。
输出：MoveIt 已有 OctoMap 及一个诊断话题，至少包含地图年龄、最近点云时间、可用体素数量/范围和传感器 TF 状态。

点云应先限距离、下采样，并依赖 MoveIt 的机器人自过滤移除可见机械臂部分。目标方块本身在接近阶段需要以局部、明确的接触策略处理，不能直接把整张环境图清空或关闭碰撞检查。

### 2. 观察姿态序列

职责：提供 3--5 个低速、关节限位内的候选观察姿态。姿态只是候选，不代表允许执行；每次仍必须通过走廊门和 Planning Scene 碰撞检查。

起始状态：按键 `1` 的零点复位完成且关节反馈确认后。第一个深度观测在原地完成，不产生额外运动。

选择规则：优先选择能使相机看到目标最后可信方位、目标颜色候选或当前地图未知边界的候选姿态；没有目标时按固定优先级遍历。候选失败不重试盲动，转向其他已验证候选；全部失败时发布 `ACTIVE_SCAN_NO_CERTIFIED_VIEW` 并保持原位。

### 3. 未知空间走廊门

职责：对每条候选观察轨迹和抓取微步路径进行额外验证。它不以“没有点”视为自由空间。

算法第一版：

1. 将轨迹按时间/关节插值离散成有限个状态。
2. 对每个状态取得机械臂碰撞几何体的保守包络；先用连杆/夹爪附近的一组采样点或胶囊近似，保留额外安全膨胀量。
3. 将包络采样点查询当前 OctoMap：只有被明确射线更新为空闲的体素允许通行；占据和未知体素均拒绝。
4. 任一点失败即拒绝整条路径，并报告最先失败的状态、连杆和原因：`OCCUPIED` 或 `UNKNOWN`。

第一版不重写 FCL 碰撞系统：普通 MoveIt 规划仍负责机器人自碰撞、已占据环境碰撞和关节约束；未知空间门只补足 OctoMap 的未知语义。

### 4. 抓取阶段接口

现有闭环微步接近保留。每个 8 mm 微步在原有目标有效性、深度质量、Planning Scene 碰撞路径和反馈到位检查之外，再调用未知空间走廊门。

发生以下任一情形时，不闭爪、不继续前进：目标失效、深度质量门失败、目标离开允许的像素/三维误差、环境点云失效、轨迹穿过占据体素、轨迹穿过未知体素、关节反馈未到位。

## 状态机

```text
ZERO_RESET
  -> INITIAL_STILL_OBSERVE
  -> ACTIVE_SCAN_SELECT
  -> ACTIVE_SCAN_VERIFY_CORRIDOR
      -> ACTIVE_SCAN_MOVE -> ACTIVE_SCAN_OBSERVE -> ACTIVE_SCAN_SELECT
      -> ACTIVE_SCAN_NO_CERTIFIED_VIEW (保持原位)
  -> SEARCH / ALIGN / TRACK_HOLD
  -> GRASP_READY
  -> PREGRASP / MICRO_APPROACH
```

目标在初始观测中已出现时，仍应先确认目标附近的抓取走廊被观测为空闲，随后可跳过额外扫描，进入现有搜索/对齐流程。任何时候目标丢失仍沿用已实现的可信历史重捕获和颜色候选重获；主动扫描只提供环境信息和更合适的观察位，不替代视觉目标认证。

## 失败处理与可观测性

- `/camera/depth/points` 超时、相机 TF 不可用、地图过期：不移动，报告 `ACTIVE_SCAN_MAP_UNAVAILABLE`。
- 第一条或后续候选路径包含未知/占据空间：不执行该姿态，记录被拒绝候选和体素类别。
- 没有任何已认证的观察位：保持当前位置，报告 `ACTIVE_SCAN_NO_CERTIFIED_VIEW`；不回放旧关节姿态或扩大速度。
- 观察途中点云失效、关节反馈超时或 Servo 碰撞状态异常：停止当前阶段，进入现有停止/视觉重获逻辑。

`runtime_monitor.py` 需要扩展为单窗口显示：地图新鲜度、当前扫描阶段、候选姿态编号、已拒绝原因、走廊结果及当前 Planning Scene/点云状态。

## 参数与默认值

所有参数在 `cube_task_real.yaml` 或独立主动扫描配置中声明，禁止把环境尺寸/坐标写死在 C++。

- `active_scan_enabled: true`
- `active_scan_max_views: 5`
- `active_scan_velocity_scaling`: 使用现有真机低速轨迹比例，具体值须在实机空场验证后确定。
- `active_scan_map_timeout_s`: 地图最大允许年龄，默认须比点云更新周期宽松但小于抓取阶段时间尺度。
- `unknown_space_padding_m`: 机械臂包络额外膨胀量，初始值须通过空场与已知障碍物实验标定。
- `unknown_space_sample_step_m` / `unknown_space_sample_step_rad`: 走廊离散分辨率，不得大于安全膨胀量的一半。

观察姿态可作为机器人关节配置保存，但它们仅定义相机观察方向与工作范围，不编码现实环境中的障碍物位置。

## 验收顺序

1. **只读验证**：在 Ubuntu/RViz 确认点云、TF、`/brain_robot_vision/filtered_points` 和 MoveIt Planning Scene 同步；不使实体机械臂运动。
2. **空场观察验证**：在清空的工作区中执行零点后原地建图；观察地图和诊断新鲜度。
3. **单候选验证**：只开放一个观察姿态，确认走廊全为空闲时才低速移动；在路径可见范围放置柔软障碍物时，候选被拒绝而不运动。
4. **多视角验证**：依次开放 3--5 个候选位，确认每个执行前都会重新验证走廊；目标遮挡时地图范围增加。
5. **抓取联调**：仅在前四步通过后，验证微步接近遇到未知/占据体素会停止而非继续前进。

不能以笔记本电脑作为碰撞测试物。对黑色/反光物体，深度质量门或地图空洞应导致未知拒绝；若要提升这类物体的可见性，优先改善照明、相机角度或增加外部相机，而不是放宽未知拒绝规则。

## 实施边界

本设计先实现会话地图状态、扫描候选状态机、未知空间门、诊断和配置；不修改已完成的 HSV 检测、深度质量门、持续跟踪、日志限制、夹爪控制协议或基础 PiPER 命令适配器，除非上述接口确有必要。

真实机械臂的“绝不碰撞”不能只由软件宣称：相机深度误差、TF 标定误差、机器人碰撞模型误差和未观测遮挡物都需要实机标定。设计的可验证行为是：在传感器和标定数据可信范围内，系统不将未知空间当作可通行空间。
