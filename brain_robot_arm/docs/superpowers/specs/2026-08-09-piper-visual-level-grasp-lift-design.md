# PiPER 视觉水平抓杯与抬升设计

## 1. 目标与范围

在已经通过 Gazebo 验证的 `SEARCH -> ALIGN -> APPROACH -> REACHED` 视觉闭环之后，增加“调整水平抓取姿态、最后视觉接近、闭合夹爪、附着杯子、竖直抬升并保持”的下一阶段。机械臂抓住杯子后停止在 `HOLDING`，本阶段不搬运、不放置，也不接入真实机械臂和头环。

杯子按装水容器处理：最终接近时相机光轴和夹爪前进轴与桌面平行，画面上方与世界 `+Z` 一致；抓住后只沿世界 `+Z` 抬升并保持末端姿态，不能倾斜杯子。

## 2. 软件边界

视觉运动继续由 `visual_search_controller` 负责。它消费目标像素误差、深度、TF和关节状态，输出受限的MoveIt Servo运动意图，并增加 `LEVEL_ALIGN`、`FINAL_APPROACH` 和 `GRASP_READY` 状态。

新增独立的抓取抬升执行节点。该节点只在收到 `GRASP_READY` 后执行 `CLOSE -> ATTACH -> LIFT -> HOLDING`，复用现有 `pick_place_node` 已验证的夹爪MoveGroup、MoveIt碰撞体附着、Gazebo杯子跟随和竖直运动实现。它不复制搜索、识别和像素控制逻辑。

Gazebo杯子附着与跟随属于仿真后端。未来实体PiPER继续使用相同的任务状态接口，但替换为实体夹爪和机械臂执行后端，不调用Gazebo服务。实体配置保持运动锁定，仿真标定值不得直接复制到实体配置。

## 3. 状态流

完整状态流为：

`SEARCH -> ALIGN -> APPROACH -> LEVEL_ALIGN -> FINAL_APPROACH -> GRASP_READY -> CLOSE -> ATTACH -> LIFT -> HOLDING`

原 `REACHED` 表示视觉搜索阶段已经到达安全调整距离。本阶段把它作为进入 `LEVEL_ALIGN` 的过渡条件，不在 `REACHED` 直接闭合夹爪。仿真按一次开始命令后可自动执行到 `HOLDING`；任何停止或急停命令都必须中断后续状态。

## 4. LEVEL_ALIGN

`LEVEL_ALIGN` 的目标是获得可装水抓取的世界水平姿态，同时继续看住杯子：

- 相机光学轴与桌面平行，即其世界 `Z` 分量接近零。
- 相机画面上方与世界 `+Z` 对齐，禁止滚转倾斜或倒置。
- 杯子目标像素为 `(320,160)`；该坐标必须参数化。
- 此状态前向速度恒为零。
- 水平像素误差用于左右朝向修正；垂直像素误差优先通过垂直平移修正，不能通过重新俯仰相机来把杯子移到目标像素。
- 相机水平姿态误差小于 `3°`、水平和垂直像素误差进入死区且连续稳定5帧后，才能进入 `FINAL_APPROACH`。

水平姿态不能通过硬编码某一个J5角度判断。控制器必须使用TF读取相机光学坐标系相对世界坐标系的实际姿态，因此J2、J3或其他关节变化后仍能判断相机是否与世界水平。

## 5. FINAL_APPROACH

`FINAL_APPROACH` 同时维持世界水平姿态和 `(320,160)` 视觉目标。控制器允许沿相机光轴低速前进，并叠加受限的横向、竖向修正；姿态修正、像素修正和前进速度均由独立上限限制。

第一轮仿真抓取深度设为可调参数 `0.08 m`。深度达到阈值、姿态仍水平、像素误差仍在死区并连续稳定5帧后，控制器发布零速度并进入 `GRASP_READY`。该数值只是Gazebo起点，必须根据杯身是否真正进入两片夹爪之间单独调整。

目标丢失、深度无效、像素偏差超过重新对准阈值、TF超时、Servo异常、碰撞或奇异点预警时，立即发布零速度，禁止进入 `GRASP_READY`。最后接近阶段不允许使用最后一次目标继续盲目前进。

## 6. CLOSE、ATTACH、LIFT与HOLDING

抓取执行节点收到 `GRASP_READY` 后：

1. `CLOSE`：调用夹爪MoveGroup执行已有 `close` 状态；失败时保持停止，不附着杯子。
2. `ATTACH`：把 `medicine_cup` 作为MoveIt附着碰撞体连接到 `gripper_base`，触碰连杆使用夹爪组链接；随后开启Gazebo杯子跟随。两步任一步失败都停止后续动作。
3. `LIFT`：以抓取时末端姿态为固定姿态，沿世界 `+Z` 规划并执行 `0.10 m` 竖直抬升。不得改变末端滚转、俯仰和偏航。
4. `HOLDING`：停止机械臂运动，保持夹爪闭合、MoveIt附着和Gazebo跟随，不自动搬运或释放。

抓取前失败时夹爪保持张开；夹爪闭合但附着失败时保持闭合并停止；杯子已经附着后抬升失败时保持闭合与附着，等待人工停止或场景重置，不能自动松爪。

## 7. 参数与接口

仿真配置增加以下参数，名称在实现时保持集中，不能散落硬编码：

- `level_target_x_px: 320.0`
- `level_target_y_px: 160.0`
- `level_angle_tolerance_rad: 0.05236`
- `level_stable_frames: 5`
- `grasp_depth_m: 0.08`
- `grasp_stable_frames: 5`
- 水平、垂直、姿态和最后前进速度上限
- `lift_distance_m: 0.10`

视觉控制器发布当前状态和是否允许抓取。抓取执行节点不得仅凭一帧深度或单独的Bool话题闭合夹爪；它只接受视觉控制器在全部门控稳定通过后发布的 `GRASP_READY`。

## 8. SSVEP、EOG与实体复用

本阶段仿真中的一次开始命令授权整条流程运行到 `HOLDING`。后续SSVEP选择目标，EOG确认开始、取消或急停；它们只改变任务授权，不能直接发送关节、笛卡尔速度或夹爪位置命令。

实体Gemini2接入前必须重新标定：相机光学坐标系、相机相对夹爪外参、目标像素 `(320,160)`、抓取深度、夹爪闭合位置、抬升方向和工作区限制。实体配置继续保持 `real_motion_enabled=false`，直到CAN、驱动、急停、空载低速动作和以上标定分别通过。

## 9. 验证顺序与验收标准

1. Windows静态检查：状态、参数、TF坐标约束和失败路径不存在未使用项或相互矛盾。
2. Ubuntu定向构建：只构建 `brain_robot_pick_place`，确认新增节点和配置安装成功。
3. Gazebo水平调整测试：前进速度为零；相机光轴最终与桌面平行，画面上方与世界 `+Z` 一致；杯子稳定在 `(320,160)` 死区。
4. Gazebo最后接近测试：保持水平姿态和目标像素，深度从安全距离下降到 `0.08 m` 附近；目标或深度失效时立即停止且不闭合夹爪。
5. Gazebo抓取测试：杯身真正进入两片夹爪之间后闭合；MoveIt与Gazebo中的杯子均完成附着。
6. Gazebo抬升测试：杯子沿世界 `+Z` 上升约 `0.10 m`，姿态不倾斜，最终进入 `HOLDING`。
7. 分层记录：Gazebo通过不代表Gemini2、实体PiPER、装水实杯或SSVEP+EOG已经通过；这些必须分别验证。

## 10. 明确不包含

本阶段不实现搬运、交付区放置、循环抓取、多类别识别、实体机械臂运动解锁和头环SDK接入。`HOLDING`验证通过后，下一阶段再增加安全搬运与放置，最后连接SSVEP选择和EOG确认、取消、急停。
