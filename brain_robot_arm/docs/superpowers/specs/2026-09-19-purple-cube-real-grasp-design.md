# 紫色方块实体抓取接入设计

## 目标

保留现有“视觉搜索 → 自动居中 → `GRASP_READY`”流程，不要求操作者手动把方块放到画面中心。目标点由 RGB-D 检测器从图像和深度实时发布。

## 数据流

1. `cube_detector` 从 `/camera/color/image_raw` 和 `/camera/depth/image_raw` 计算方块中心及深度，发布 `/brain_robot_vision/target_point_camera` 与 `/brain_robot_vision/target_size`。
2. 抓取执行器接收相机坐标系目标点，通过 TF 查询相机光学坐标系到 `gripper_base`/世界坐标系的变换，生成夹爪目标位姿。这里的固定 TF 是相机安装外参，不是操作者手工输入的方块偏移。
3. 视觉控制器继续只负责搜寻和对准；`GRASP_READY` 后由显式抓取触发进入实体执行，避免识别节点直接闭爪。
4. 实体夹爪动作复用已经在 `auto_sequence_speed50.py` 验证过的 SDK 命令：张开 `GripperCtrl(50000, 1000, 0x03, 0)`，收紧 `GripperCtrl(40000, 200, 0x03, 0)`。不把 MoveIt 的仿真命名目标当作实体夹爪接口。

## 实体运动边界

- 不增加固定的预抓取、接近或抬升距离参数；目标位姿直接由相机目标点和现有末端姿态策略生成。
- 不直接调用当前禁用实体执行的 `MoveGroupInterface::execute()`；实体关节轨迹必须经过现有低速适配器和 `piper_ctrl_single_node`。
- 默认仍保持 `real_grasp_enabled=false`。只有目标点新鲜、TF 可用、关节反馈新鲜、适配器已启用/已武装并收到显式抓取触发时，才允许输出实体抓取命令。
- 丢失目标、TF 超时、关节反馈超时、急停或适配器失联时立即停止输出并保持夹爪，不自动继续。

## 验收标准

1. 目标在画面外或偏离中心时，系统自动搜寻并居中，不需要手动调整目标。
2. `GRASP_READY` 阶段可以稳定收到相机目标点和目标尺寸，且 TF 查询成功。
3. 显式触发后先张开夹爪，再执行低速实体轨迹；夹爪收紧命令与现有脚本一致。
4. 未满足任一前置条件时只发布诊断状态，不向实体 PiPER 发布运动命令。
5. 仿真配置和现有视觉搜索逻辑保持不变。

## 当前未假设的硬件事实

相机到实体夹爪的 TF 是否已经准确标定、目标点到实际指尖接触点的误差、以及 `40000` 对当前实体夹爪的实际夹持效果，必须在真机低速、空抓测试中验证；源码不能替代这三项测量。
