# PiPER 紫色方块持续跟踪与闭环抓取设计

日期：2026-09-21  
状态：A、B 与 C1 源码已完成；C2 需 Ubuntu/RViz 实机验收

## 背景与已确认事实

当前实体流程按键 `1` 会执行零点复位、固定观测姿态、搜索和图像居中；按键 `2` 在 `GRASP_READY` 后启动抓取。紫色方块检测、RGB-D 深度、相机到 `base_link` 的 TF、实体关节反馈和 PiPER 命令链均已在此前运行中分别验证过。

设计开始时，控制器在满足连续居中帧数后会转入 `GRASP_READY` 并停止控制循环，因此方块在首次稳定居中后再次被移动时，不能自动重新进入 `ALIGN`。这解释了“有时仍跟踪、有时不再跟踪”：未满足稳定帧数时仍处于 `ALIGN`，达到稳定帧数后则停止。A1 已将 `GRASP_READY` 改为持续监视状态。

设计开始时，`LAST_PATH_REACQUIRE` 只保存 J1/J5 最近一次非零速度方向，并从丢失时的当前位置固定延伸一段。A2--A4 已改为使用最后可信三维历史、短时预测和颜色候选重获；候选仍不能直接授权抓取。

设计开始时，视觉控制命令包含 J1/J5 主控制、J2/J3 辅助和 J4/J6 水平锁；这些关节耦合可能令夹爪在空间中前进，Servo 碰撞检查也被关闭，`forward_allowed` 则没有订阅者。B1--B3 已将真机视觉配置收敛为 J1/J5、删除无效 `forward_allowed`，并启用 Servo 碰撞检查；点云进入规划场景和实体减速/硬停效果仍待实机验收。

## 目标

1. 对齐后保持持续目标监视：目标偏移、丢失或深度失真时，能自动停止当前接近并恢复视觉对齐或重捕获。
2. 使用最后可信视觉历史，而不是固定关节偏移，完成短时预测重捕获和颜色候选重捕获。
3. 视觉对齐阶段不执行主动接近目标的动作；任何可能向障碍物靠近的运动必须经明确的碰撞与距离约束。
4. 抓取阶段采用预抓取规划和闭环微步接近，而不是一次发布完整、不可中断的直线接近轨迹。
5. 日志空间受控，不通过取消系统账户密码来获得后台清理权限。

## 非目标

- 本阶段不引入通用的深度学习目标检测网络。
- 不把颜色候选直接作为抓取目标。
- 不把点云接入视为已完成的实机碰撞保护；必须单独验证点云、TF、自过滤与规划场景。
- 不改变按键语义：`1` 是零点复位后搜索/持续对齐，`2` 是抓取，`0` 是零点复位，`Ctrl+C` 是失能并退出。

## 实施顺序与验收

### A. 持续跟踪与重捕获

- [x] **A1：将 `GRASP_READY` 改为持续监视的 TRACK_HOLD。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 在不发布运动命令的情况下持续检查 `target_valid`、像素误差、深度有效性和时间戳。
  - 目标偏移超过对齐阈值时，启动 Servo 并返回 `ALIGN`。
  - 目标丢失时进入最后可信轨迹重捕获，不永久停在 `GRASP_READY`。
  - 验收：首次居中后手动移动方块，机械臂应重新对齐。

- [x] **A2：保存目标历史。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 保存最近约 0.3--0.4 秒的有效样本：相机坐标点、变换后的 `base_link` 点、像素误差、深度、对应关节状态和时间戳。
  - 当前实现仅记录 `target_valid=true` 且目标点/像素误差新鲜的样本；检测器仅在当前深度检查通过时发布三维点。深度离散度与连续帧质量门留给 C1。
  - 新增诊断话题 `/brain_robot_visual_control/target_history`，报告样本数、最近样本年龄、相机点、`base_link` 点、窗口速度估计、像素误差和保存的关节数。
  - 验收：诊断话题能报告最近可信目标的时间、位置和速度估计。

- [x] **A3：改写最后路径重捕获。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 首选最近可信目标在 `base_link` 的位置和近期速度估计，形成受预测时域限制的重捕获参考点。
  - 只允许一到两个小幅重捕获步；失败后转入颜色候选/局部搜索，禁止盲目执行固定 0.20/0.15 rad 关节偏移。
  - 记录最后可信位置而非简单回放旧关节姿态：腕部相机随机械臂运动，直接回放旧关节姿态不等于追踪物体运动方向。
  - 当前实现以最近 0.40 秒 `base_link` 历史的末点和速度估计生成 0.25 秒预测点；将该点投影回当前腕部相机，按像平面方向计算受限 J1/J5 目标。每次丢失最多尝试两步，每步最大 0.60 rad；历史、TF 或预测深度不可用时直接转入局部搜索。
  - 验收：方块短暂出画后，系统先沿最后可信视觉趋势尝试重捕获，再进入候选颜色搜索。

- [x] **A4：接入现有颜色候选流。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 将候选颜色流用于预测重捕获和局部搜索的优先方向。
  - 候选必须再次通过紫色、矩形性、尺寸、深度和稳定性检查，才恢复正式目标。
  - 预测重捕获中发现候选时，状态会明确标为 `COLOR_CANDIDATE_REACQUIRE_AFTER_PREDICTION`；局部搜索中发现候选仍使用 `COLOR_CANDIDATE_REACQUIRE`。两条路径都只能进入 `ALIGN`，不能进入 `GRASP_READY`；只有检测器恢复 `target_valid=true` 后，原有几何、尺寸、深度和稳定帧门才会重新授权抓取。
  - 验收：相近紫色干扰物不会被直接抓取。

### B. 视觉阶段的空间前进与碰撞约束

- [x] **B1：记录并隔离空间前进来源。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 为每条发送至 Servo 的命令记录状态、关节名、速度和来源阶段。
  - 分别验证 J2/J3 辅助、J4/J6 水平锁定、PREPARE 轨迹和抓取轨迹是否造成夹爪向前位移。
  - 新增瞬态诊断话题 `/brain_robot_visual_control/command_diagnostic`：视觉 `JointJog` 报告控制状态、命令来源、关节名和速度；零点复位与观测姿态轨迹报告来源和最终关节目标。`runtime_monitor.py` 已显示该话题；抓取轨迹继续使用既有 `/brain_robot_grasp/diagnostic` 的 `REAL_ARM_TRAJECTORY_PUBLISHED` 记录。
  - 验收：每一次观察到的空间前进均能对应到唯一命令来源。

- [x] **B2：视觉阶段禁止主动接近。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 视觉搜索/居中只允许经验证的横向和俯仰修正；任何会缩短夹爪到障碍物距离的辅助关节运动必须受额外限制或移除。
  - `forward_allowed` 要么接入实际命令门，要么删除，不能保留无效的安全语义。
  - 真机配置关闭 J2/J3 的 `alignment_assist`，并将 J4/J6 水平锁的关节列表置空；控制器现在允许空水平锁列表。因此 `SEARCH`、`LAST_PATH_REACQUIRE`、`LOCAL_SEARCH`、`ALIGN` 和持续监视阶段只会发布 J1/J5。没有订阅者的 `forward_allowed` 已删除，而不是继续发布不产生执行效果的布尔值。
  - 验收：按 `1` 在电脑旁只执行搜索/图像居中，不发生无授权接近。

- [x] **B3：启用 Servo 碰撞检查。**（配置已实现；待 Ubuntu 实机验证）
  - 将 `check_collisions` 改为启用，并确认 Planning Scene 能获得相机点云环境。
  - `piper_servo_real.yaml` 现已启用 `check_collisions: true`。启动文件已将 MoveIt 的 `PointCloudOctomapUpdater` 指向 `/camera/depth/points`，并把地图坐标系设为 `base_link`；Servo 在非主 Planning Scene Monitor 模式下会向 MoveIt 请求场景状态。点云是否实际进入场景及自过滤是否正确仍属于实机验收，不以配置替代结论。
  - 验收：接近环境点云或碰撞物时，Servo 状态可观察到减速或硬停；真实机械臂不以电脑作为撞击测试对象。

### C. 感知与深度置信度

- [x] **C1：增加深度质量门。**（源码已实现；待 Ubuntu 构建和实机验收）
  - 目标必须满足有效样本数、深度中位数离散度、连续帧深度变化和非裁剪条件。
  - 颜色/形状有效但深度不可信时，允许视觉跟踪，不允许接近或抓取。
  - 检测器现以掩膜内深度中位数、median absolute deviation（MAD）、相邻帧中位数变化和连续稳定帧数计算严格的 `/brain_robot_vision/depth_valid`。真机默认门槛是最少 10 个样本、MAD 不大于 12 mm、相邻帧变化不大于 30 mm、连续 3 帧稳定，且方块不能被图像边缘裁剪。
  - `/brain_robot_vision/target_valid` 保持颜色/形状确认语义，故深度门失败时视觉控制器仍可搜索、居中和重新跟踪；`/brain_robot_vision/depth_valid=false` 会阻止 `/grasp_lift_executor/execute`，而抓取过程中门失效也会返回视觉重获。
  - 新增瞬态诊断 `/brain_robot_vision/depth_diagnostic`，以及调试画面的 `MAD`、`dZ`、稳定帧和拒绝原因；`runtime_monitor.py` 同时显示该诊断。
  - 验收：黑色、镜面或强反光背景引发深度跳变时，系统拒绝抓取并报告原因。

- [ ] **C2：确认点云碰撞模型。**（配置已存在；必须实机验证）
  - 验证 `/camera/depth/points` 到 `base_link` 的坐标一致性、Octomap 更新和机械臂自过滤。
  - 现有启动文件已使用 `PointCloudOctomapUpdater`，输入 `/camera/depth/points`、输出自过滤后点云 `/brain_robot_vision/filtered_points`，地图坐标系为 `base_link`；这只是接入条件，并不证明规划场景实际收到了环境点。
  - Ubuntu 验收命令：`timeout 5s ros2 topic hz /camera/depth/points`、`timeout 5s ros2 topic hz /brain_robot_vision/filtered_points`，以及 `timeout 8s ros2 run tf2_ros tf2_echo base_link camera_color_optical_frame`。随后在 RViz 添加 Planning Scene 与 `/brain_robot_vision/filtered_points`，放置桌面障碍并观察 Octomap/规划路径；不能拿电脑作为撞击测试物。
  - 验收：RViz/Planning Scene 中能看到桌面类障碍，规划路径会避开它们。

- [x] **C3：训练决策。**（工程决策已记录）
  - 固定相机、紫色方块与有限光照下，优先使用 HSV 自适应、时间滤波和深度质量门，不训练模型。
  - 当存在大量相似紫色干扰、光照跨度大、遮挡频繁或需要多类别物体时，再采集真实 RGB-D 数据训练检测/分割模型。
  - 即使引入训练模型，黑色/反光材质的深度问题仍由深度质量门和点云处理解决。

### D. 闭环抓取

- [ ] **D1：保留规划预抓取，替换完整直线接近。**
  - 预抓取位姿可由 MoveIt 规划，但真实执行后必须由 `/joint_states` 确认到位。
  - 任何计划失败、反馈超时或状态偏差都回到视觉跟踪。

- [ ] **D2：实现微步闭环接近。**
  - 每步只接近 5--10 mm。
  - 每步前后重新检查像素误差、目标有效性、深度置信度、点云/碰撞距离和关节反馈。
  - 目标偏移、丢失、深度不稳定或碰撞风险出现时，立即停止接近并回到 A 部分。

- [ ] **D3：加入短时运动预测。**
  - 以最近可信目标三维速度和控制/通信延迟预测下一微步目标。
  - 预测仅在速度估计稳定且预测时域很短时使用；不对长期丢失目标进行盲追。

- [ ] **D4：夹爪闭合和抬升。**
  - 仅在最终对齐、深度稳定、微步接近完成后闭合。
  - 闭合后先确认抓取条件，再执行抬升。
  - 验收：各阶段发布明确状态；任何失败都不继续闭爪或抬升。

### E. 日志与磁盘空间

- [ ] **E1：验证日志边界。**
  - 确认应用日志、ROS 日志、`syslog*` 与 `kern.log*` 在长期运行中不无限增长。

- [ ] **E2：配置受限免密日志清理。**
  - 不取消虚拟机账户密码。
  - 仅对日志截断、journal 清理等白名单命令授予免密 sudo，或以受限 systemd 服务运行。
  - 验收：重启后无需人工输入密码，日志守护仍能清理允许范围内的系统日志。

- [ ] **E3：磁盘状态告警。**
  - 根分区超过阈值时发布明确告警，避免继续启动会产生高频日志的新流程。

## 开始每一项前的固定流程

1. 重新读取本设计文档、当前状态文档及该项涉及的源码和当前生效配置。
2. 明确该项的输入、状态变化、输出和验收方式。
3. 仅做完成该项所需的最小修改。
4. 先编译受影响包，再进行最低风险的 ROS/仿真验证；需要实机动作时由操作者在清空工作区后执行。
5. 将实测结果、未验证部分和问题更新到状态文档，再提交 Git。
