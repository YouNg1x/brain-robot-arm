# PiPER 腕部相机连续覆盖搜索设计

本文件是对 `2026-08-09-piper-search-align-approach-design.md` 中搜索轨迹部分的后续修订；涉及 J1/J5 搜索范围、反向条件和验收现象时，以本文件为准。原设计中的感知接口、对准、接近、安全门控和实体复用约束继续有效。

## 1. 目标与范围

本次只修改 `visual_search_controller` 的无目标搜索轨迹。搜索时，J1 持续左右摆动，J5 先向下、再向上改变相机俯仰角，在上下边界处额外完成一次完整的水平覆盖。任意阶段检测到目标后，搜索立即停止，沿用现有 `ALIGN -> APPROACH` 流程完成目标居中和沿相机方向靠近。

本设计不修改红杯检测器、夹爪控制、接近算法和 SSVEP+EOG 授权接口。根据 Gazebo 相机视角复测，本次修订同时调整 MoveIt2 的仿真准备姿态；Gazebo 与实体 PiPER/Gemini2 继续使用独立配置，实体配置保持锁定。

## 2. 选定方案

采用连续覆盖扫描，不采用 J1/J5 完全独立反向，也不采用每个 J5 角度停下来逐层扫描。J1 始终在水平边界间往返，J5 在垂直边界间低速移动；J5 到达任一垂直边界后保持不动，直到 J1 从该时刻起至少到达过左右两个边界，才允许 J5 反向。

与立即反向相比，该方案能够覆盖垂直视野边缘；与逐层栅格相比，它保持连续运动，搜索时间和动作复杂度更低。边界覆盖使用关节状态和端点命中事件判断，不依赖固定等待时间，因此仿真速度变化不会改变“充分扫描”的含义。

## 3. 仿真参数

- 初始观察角：J1=`0.00 rad`、J2=`+0.98 rad`、J3=`-0.75 rad`、J4=`0.00 rad`、J5=`+0.30 rad`、J6=`0.00 rad`。
- J1 搜索范围：`-0.98～+0.98 rad`，与 Gazebo ros2_control 的 `[-1.00,+1.00] rad` 限位各保留 `0.02 rad` 余量。
- J5 下方边界：`+0.95 rad`，正方向在当前 Gazebo 模型中表示相机向下看。
- J5 上方边界：`-0.60 rad`。
- J1、J5 的速度继续由 `horizontal_search_speed` 和 `vertical_search_speed` 参数限制。
- 仿真水平对准符号：`horizontal_error_sign=-1.0`；这是腕部虚拟相机与 J1 正方向的标定结果，不得直接复制到实体 Gemini2 配置。
- J4/J6 在搜索、对准和接近期间继续锁定到各自标定的水平角度。
- 搜索总超时保持 `75 s`。

关节边界保留控制器余量，不把仿真 ros2_control 的端点直接作为搜索目标。以上数值不得复制到实体机械臂配置。

J2 从 `+0.90` 增加到 `+0.98 rad`，仍在 Gazebo ros2_control 的 `+1.00 rad` 上限内；J3 从无法完整执行的 `-1.30 rad` 改为接口范围内的 `-0.75 rad`。模型正运动学估算表明，当 J5 到达 `+0.95 rad` 时，相机光轴相对竖直向下的夹角可由实际受限姿态下约 `46°` 降至约 `27°`。该结果只是模型计算，最终视角、可见范围和碰撞情况以 Gazebo 现象为准。

## 4. 状态与转换

### 4.1 SEARCH_DOWN

进入完整搜索时，J1 从当前角度优先向负方向运动，随后在 `-0.98～+0.98 rad` 间持续往返；J5 从观察位向 `+0.95 rad` 移动。负方向只是“无目标完整搜索”的初始方向，不参与目标对准。J1 到达水平边界时只反转 J1，不能暂停或改变 J5。

J5 到达下方边界后转入 `BOTTOM_SCAN`，并清空本次边界覆盖记录。

### 4.2 BOTTOM_SCAN

J5 保持在 `+0.95 rad`。J1 继续往返；控制器分别记录“到达左边界”和“到达右边界”。只有两个标志都成立后，才清空覆盖记录并让 J5 反向，进入 `SEARCH_UP`。

### 4.3 SEARCH_UP

J1 继续独立往返；J5 向 `-0.60 rad` 移动。J5 到达上方边界后转入 `TOP_SCAN`，并清空边界覆盖记录。

### 4.4 TOP_SCAN

J5 保持在 `-0.60 rad`。J1 继续往返，直到左右两个边界从进入本状态后都至少到达一次。随后清空覆盖记录，让 J5 反向并重新进入 `SEARCH_DOWN`。在搜索总超时前，上述循环可以重复。

### 4.5 目标获取与后续动作

上述四个搜索阶段都持续读取 `target_valid` 和带时间戳的目标数据。仿真配置获得 1 帧新鲜有效目标后，控制器必须立即先发布 J1/J5 零速度，再进入现有 `ALIGN` 状态；实体 PiPER/Gemini2 配置继续要求连续 3 帧，避免单帧噪声误触发。

进入 `ALIGN` 后，J1 不再使用搜索方向，而只使用水平像素误差闭环控制。仿真标定关系为 `v_J1 = clamp(-Kp × dx)`：目标在画面右侧时 `dx>0`，J1 向负方向运动；目标在画面左侧时 `dx<0`，J1 向正方向运动；误差进入死区后 J1 停止。J5 同理按垂直误差控制。只有目标稳定居中且深度有效后才能进入 `APPROACH`，沿相机光轴低速靠近。画面边缘出现目标时的“立即靠近”在控制语义上是立即停止搜索并开始居中，不允许跳过居中直接向前。

目标在 `ALIGN` 或 `APPROACH` 中丢失时，继续使用现有的局部重搜索；局部搜索失败后才重新进入完整覆盖搜索。

## 5. 实现边界

控制器内部增加垂直搜索阶段和两个水平端点命中标志。现有 `SEARCH` 状态对外保持不变，阶段作为搜索状态内部数据，避免扩大 ROS 接口和一键启动脚本的改动范围。搜索方向话题增加当前阶段，例如 `PHASE=BOTTOM_SCAN J1=POSITIVE J5=HOLD_DOWN`，用于仿真观察和故障定位。

检测器仍只输出目标像素误差、深度和有效性；它不知道关节名称或 Gazebo。运动后端仍通过现有 Servo 话题接收受限速度意图。实体机械臂、Gemini2 和头环接入只替换配置、话题映射、标定及授权层，不改本搜索状态机。

## 6. 安全与异常处理

- 任意搜索阶段收到停止或急停命令，立即发送零速度并离开活动状态。
- 关节状态丢失或超过新鲜度阈值，进入 `FAULT`，不继续估计运动。
- 搜索命令始终受速度上限、软件边界和 Servo 碰撞/奇异性检查约束。
- 达到 `75 s` 仍未发现目标，进入 `STOPPED`，等待新的人工或脑机授权，不无限搜索。
- 实体配置继续保持 `real_motion_enabled=false`；只有完成关节方向、软限位、相机外参、速度、急停和空载测试后才能单独启用。

## 7. 验证标准

1. Windows 静态检查：配置字段、状态转换和边界计数不存在遗漏或未使用项。
2. Ubuntu 定向编译：只构建 `brain_robot_pick_place`，确认 C++ 与 launch/config 安装成功。
3. Gazebo 无目标测试：J1 全程往返；J5 依次执行向下、下边界保持、向上、上边界保持；每个保持阶段必须在 J1 左右边界均命中后结束。
4. Gazebo 目标测试：目标可在四个搜索阶段中的任一阶段被捕获；捕获后 J1/J5 搜索速度归零并进入 `ALIGN`。目标在画面右侧时 J1 实际关节位置必须向负方向变化，目标在左侧时必须向正方向变化，且水平误差绝对值应持续减小；随后才允许居中和靠近。
5. Gazebo 无目标初始方向测试：从 J1 零位开始搜索时，实际 `/joint_states` 中的 J1 必须先进入负角度；没有目标时应到达 `-0.98 rad` 附近后反向。检测到目标时允许提前中断，不要求为了展示幅度而继续扫到边界。
6. 超时与急停测试：75 秒超时、停止命令和急停均不留下持续非零命令。
7. 分层记录结果：Windows 检查、Ubuntu 编译、Gazebo 现象、Gemini2 实测、实体 PiPER 测试和 SSVEP+EOG 测试分别记录，不能互相替代。
